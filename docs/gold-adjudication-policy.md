# 金样验收与改判政策（预注册）

> 状态：**v1.0 预注册（2026-09-23）**。本文档在 v0.5 双考生实测（E17）之后、
> 任何后续 API 轮与外部复核之前成文；自本文档落款起，对金样的全部改动按此
> 规则执行并可被审计。此前已发生的历史案例见 §5 归档（含不合格操作，如实保留
> 作为「gold fitting 风险」的实证素材）。

## 1. 要解决的问题

金样消融（同份考生答案在 gold 修正前后重判）是本基准的核心效度方法，但它
同时制造了「gold fitting」攻击面：**如果可接受答案集合是在看到考生作答之后
扩张的，且扩张后分数上调，就无法自证这是效度修复而非向考生放水**。历史数据
（§5）显示同份答案经多轮口径修正分数单调上升（31.58→86.84→93.10），审稿人
完全可以读成「评分标准拟合到考生身上」。本政策把「什么条件下允许改金样」
在事前写死。

## 2. 预注册规则（改动合法性的充要条件）

对任一题的 gold / acceptable_articles / acceptable 枚举的改动，**必须同时**满足：

1. **法律依据独立于考生作答**：新答案的合法性必须能仅凭官方法条文本
   （lawkb 内含 text_hash 的条文）+ 法学推理独立证成，写明条文号与推理链。
   「考生引了 X 所以 X 应该算对」不构成法律依据。
2. **多解缺口登记**：属「金样未穷尽合法解」的，登记为 `multi_answer_gap`；
   属「金样引用条号/数值/期数错误」的，登记为 `gold_bug`。两类分开统计，
   消融报告分列。
3. **双向对等**：扩张 acceptable 集合时，必须同时检查并声明该改动**不会**
   使明显错误的答案（如引错法的其他条、引修正前已废止版本）变为可接受。
   检查方法：对改动后的谓词跑 random/rules 基线与 mock:gold 自证，基线分
   不得因此上升超过 1 分。
4. **记录落档**：写入 `docs/gold-item-review-log.md`（题号、缺陷类型、依据
   条文、改动人、日期、重判前后分差）。代码注释不是审计底稿。
5. **消融留痕**：改动前后对**同一份考生答案**重判，分差进测量效度审计
   （paper-outline §3.5 第 3 道）；连续多轮对同一族题改 gold 须在论文中披露
   累计修正量。

## 3. 流程

```
发现疑点（考生轮/自审/外部反馈）
  → §2.1 独立法律依据核证（逐字比对 lawkb text + 官方来源）
  → §2.3 基线与金样自证回归（ci_gate 必须全绿）
  → §2.4 登记 review-log
  → §2.5 消融重判 + 留档
  → 提交（commit 信息注明 [gold:<类型>:<题号>]）
```

对外部复核人（非作者）的要求：**复核人必须盲于考生作答**，仅依据题面、
法条与推理判断 gold 是否正确；考生答案只用于复核后的消融重判。

## 4. 禁止事项

- 禁止在未核证官方文本的情况下（仅凭检索摘要、二手转载）改 gold；
- 禁止为了使特定模型/考生得分上升而扩 acceptable（动机审查以 §2.1 记录为据）；
- 禁止只改数据不改对应测试（tasks/*/tests 与金样必须同步，ci_gate 锁定）；
- 禁止改动 holdout 金样（冻结后进入双人复核流程，另行管理）。

## 5. 历史案例归档（预注册前，含不合格操作）

| 案例 | 类型 | 处置 | 合规性 |
|---|---|---|---|
| a-006 引民法典 526 条被判 0 → 补入 acceptable | multi_answer_gap | 有法条依据；但**系见考生答案后扩张**且分数上调（72→76） | 依据合格，流程不合规（无预注册、无双向对等检查）——保留为攻击面实证 |
| at-019 金样锚「民间借贷规定 25 条」实为利率条款，正确为 16 条（2021 修正重编号） | gold_bug | 三来源核证后改锚，考生引 16 者重判得分 | 部分合规（核证充分，登记缺失） |
| at-022 金样锚「时间效力规定 27 条」与保证方式无关，正确路径为第 1 条第 2 款+担保法 19 条 | gold_bug | wikisource 全文证伪 28 条=附则假设后改锚；acceptable 双路径设计 | 合规（先证伪再改） |
| cx-007 期望值按 3 期计算（7470），题面为 6 期复利（应为 11863.40） | gold_bug | 双考生独立算得 11863.41 暴露；修 generator+gold+test 三处 | 合规（发现即修） |

以上案例已在 paper-outline §9 E17 披露 4/62 缺陷率；本政策落地后，新增改动
按 §2 全流程执行，§5 的不合格操作不再发生。
