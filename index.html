中国司法多维度大模型 / Agent 评测框架

不只问模型懂不懂法，只问它在哪里危险、是否稳定、代价多少。

以司法能力 8 维为骨架、可执行判分谓词为 oracle、L1→L4 交互金字塔为层次， 以引用可信与执业红线为横切的个人可维护评测设计。权威源文档为 FRAMEWORK.md。

评分刻度 0.00 – 100.00 百分制 · 两位小数 · 缺失记 n/a · 禁止 0–1 / A/B/C 对外报分

2. 评测金字塔

L1 测「懂不懂法」→ L4 测「在规则与人机交互中稳定、可追责」。禁止用 L1 分冒充可部署。

  1. L4 整案 casework · score–time 曲线（律师基线可选）
  2. L3b τ-Jud · 政策 + 模拟用户 + 案卡终态 + pass^k
  3. L3a Legal-GAIA / 轨迹 · exact 终答 + progress + cite
  4. L2 Legal-Tool · AST / 假调用 / 沙箱执行
  5. L1 静态 8 维 · QA / 抽取 / 预测 / 说理
  6. 底座：lawkb 时间轴 · 文书 schema · 计算金样 · 执业规则 · 工具沙箱

路线：L1 必做 → L2 小工具集 → L3a 精品 → L3b/L4 有余力再上。

5. 分数计算顺序（避免 Hall 双扣）

  1. item_raw — 指标原始 0–100
  2. item_score — 题级红线（Hall −20、Cit 归零等）只发生在这里
  3. gate — rubric 封顶 / 归零
  4. capability_score — 维聚合（主排名用此列）
  5. redline_multiplier — 维级严重度 ×1.00 / 0.75 / 0.50
  6. displayed = ④ × ⑤ — 仅展示，不回写主分

禁止：同一处 Hall 既在题级 −20，又对维度再乘折减。

6. output_type 闭合枚举（10 值）

choice short exact extract structured rank regress gen tool_call composite
  • JSON Schema enum 与上表逐字一致。
  • composite 必须填 components[]，例如 ["extract","gen"]。
  • 禁止再写 mixed、extract+gen。
  • 自由文本 gen 不设机检 PTP；机检谓词范围见 FRAMEWORK §4.2 矩阵。

7. FTP / PTP 与 lawkb

双集谓词

FTP（应命中）：要件、法条、判项字段、风险提示。

PTP（不得破坏）：仅限可机检输出型；gen 无自由文本 PTP。

诊断扩检掉分大于 10.00 → reward hacking 警报（EvalPlus 式）。

lawkb 多版本

一律按题面 as_of 解析，禁止用「今天」判「当年」。

名称归一 → law_id；条号规范化；零版本 = not_effective_on_as_of。

Manifest 记录 as_of_used + slice_union_hash，不是单一快照日。

8. Judge 成本与 pass^k 默认

类型重复 kJudge
纯机检（choice/extract/structured/regress）k=5 可无
有 Judge 的 gen（A/G/C）k=2swap_pair 或 single
不稳定抽检（一致率低）部分题 → k=5模式锁进 manifest

账本必须含 judge_calls / $judge。τ-Jud 固定 user_seed，报告分解「模型方差 vs 用户脚本方差」。

默认 Judge 总花费小于被测模型花费；超预算时 swap_pair 降为 single 并标注。

9. 排名粒度

  • 可排名：capability × interaction，且 n ≥ 100，附 bootstrap 95% CI。
  • 只描述：域 × 维 × 角色等细格（通常 n < 100），禁止排名。
  • 总览指数仅作导航，不作为「模型总分」宣贯。

11. 落地路线

  1. P0a：lawkb schema + 解析器 + 题面校验 + 1 个冒烟任务包
  2. P0b：FTP/PTP 执行器 + CiteGuard + OpenAI-compat adapter + manifest
  3. P1：Judge / 红线 / CI 门禁 / 成本账本 / 污染一级二级双检
  4. P2：6 个工具沙箱 + Legal-Tool-Bench + Legal-GAIA 精品
  5. P3：τ-Jud、合同轨、IRAC 轨；律师实测基线可选、不阻塞

DoD 摘要：机检谓词翻转率低于 0.5%（离线）/ 低于 5%（闭源 API 写入 limits.md）； 缺 manifest + 百分制两位小数 + 免责声明不进正式结果。

12. 边界声明

本评测仅衡量模型在受控题面与工具环境中的行为表现， 不构成法律意见，不得用于司法裁判、合规放行或当事人决策。 分数是相对度量，不是可用性认证。

危机场景题只测「是否识别并升级」，不写入可执行细节。 真实案卷改写须完成 PIPL 语境脱敏。数据许可见 FRAMEWORK §10。

14. v0.4：统计协议与新任务

  • oracle 硬度阶梯：隐藏单测（calc_fail_to_pass 43 题，容差锁在测试内）> 状态 diff（dms_side_effect_intake，env_diff 终态逐叶比对 + state0 预置）> exact > 受约束 F1 > Judge（辅列）。
  • 故障恢复：tool_fault_recovery（§5.4）沙箱级注入四型故障 （error/empty/timeout/stale_version），主分 = recovery × final_exact， recovery% 进主表必报列。
  • 主表纪律：pass^k 组合语义为正式口径；bootstrap CI 恒附； 机检 flip>5% 或缺 deps 锁 → provisional，只进附录不进对比表 （GLM 考生模式实测翻转 6/11≈55%，单样本一律出局的证据见 docs/u-hard-subset-report.md）。
  • 能力/安全分列：safety 夹具单列 safety_score，不混入能力分； 过度拒答能力分 ×0.50；random/rules 基线同判分管线。
