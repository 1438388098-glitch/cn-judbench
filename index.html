分数计算顺序（Hall 不双扣）

  1. item_raw — 指标原始 0–100
  2. item_score — 题级红线（Hall −20 / Cit 归零等）只在此步
  3. gate — rubric 封顶或归零
  4. capability_score — 维聚合（主排名用此列）
  5. redline_multiplier — 维级严重度 ×1.00 / 0.75 / 0.50
  6. displayed — 仅展示 = ④ × ⑤，不回写主分

output_type 闭合枚举

choiceshortexact extractstructuredrank regressgentool_call composite

共 10 个合法值。复合任务必须 output_type: composite 且填 components（如 ["extract","gen"]）。 禁止再写 mixed / extract+gen。 自由文本不设机检 PTP；机检谓词范围见 FRAMEWORK §4.2 矩阵。

FTP / PTP 与 lawkb

双集谓词

FTP 应命中：要件、法条、判项字段、风险提示。

PTP 不得破坏：仅限可机检输出型（extract/structured 等）；gen 无自由文本 PTP。

诊断扩检掉分 > 10.00 分 → reward hacking 警报。

lawkb 多版本

按题面 as_of 解析条文版本，禁止用「今天」判「当年」。

名称归一 → law_id；条号规范化；零版本 = not_effective_on_as_of。

manifest 记 as_of_used + slice_union_hash。

Judge 成本与 pass^k 默认

类型重复 kJudge
纯机检k=5 可无
有 Judge 的 genk=2swap_pair 或 single
不稳定抽检→ k=5（20% 题）锁定进 manifest

账本含 judge_calls / $judge。τ-Jud 固定 user_seed，报告分解模型方差 vs 用户脚本方差。

排名粒度

  • 可排名：capability × interaction，且 n ≥ 100，报 bootstrap 95% CI
  • 只描述：域 × 维 × 角色细格子（通常 n < 100）— 禁止排名
  • 总览指数仅导航，不作「模型总分」宣贯

边界声明

本评测仅衡量模型在受控题面与工具环境中的行为表现， 不构成法律意见，不得用于司法裁判、合规放行或当事人决策。 分数是相对度量，不是可用性认证。
